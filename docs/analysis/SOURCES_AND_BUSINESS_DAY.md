## 2. Расчётный день

### 2.1. Где определяется граница (подтверждено кодом)

Отдельной настройки или сущности «расчётный день» нет. Граница зашита в коде распределения и в быстрых фильтрах
отчётов. Часовой пояс — общий для приложения `config/app.php: 'timezone' => 'Europe/Moscow'`; обращения к часовому
поясу салона в коде не найдено. Используется **текущее время сервера** (`Carbon::now()`), а не время обращения из
внешней системы.

| Правило                                                                                                                                                                                                                                                                                          | Файл и метод                                                                                                                                                                                                        | Пример (время Москвы)                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Граница 19:00** для всех салонов, кроме салона 9. Если сейчас в интервале `[19:00; 23:59:59]` — «рабочий день» считается завтрашним: график берётся по дню недели завтра, окно нагрузки `[сегодня 19:00; завтра 19:00]`. Иначе — график сегодняшнего дня и окно `[вчера 19:00; сегодня 19:00]` | `OrderAddedEventListener::distribute`; копии в `OrderAddedPvEventListener`, `OrderAddedExcelEventListener`, `OrderDistributeService::distribute`, `ImportJustweController`                                          | пн 18:59 → график понедельника, нагрузка с вс 19:00 до пн 19:00; пн 19:00 → график вторника, нагрузка с пн 19:00 до вт 19:00                                                                                                     |
| **Исключение: салон 9 — граница 18:30** (и для дня недели, и для окна нагрузки)                                                                                                                                                                                                                  | те же методы, условие `if ($showroom_id === 9)`                                                                                                                                                                     | салон 9, пн 18:45 → уже график вторника                                                                                                                                                                                          |
| Проверка «работает ли сотрудник» для повторной заявки всегда использует 19:00, **даже для салона 9**                                                                                                                                                                                             | `OrderAddedEventListener::checkUserSchedule`, `OrderDistributeService::checkUserSchedule`                                                                                                                           | салон 9, пн 18:45: новый сотрудник выбирается по графику вторника, а прежний владелец повтора проверяется по графику понедельника                                                                                                |
| Граница 19:00 без исключения салона 9 и без фильтра по типу сайта                                                                                                                                                                                                                                | `DistributeService::distribute` (импорты PV/Justwe, график `programmatic_schedules`), `ImportAura/Autodom/Autopole/AvangardController`, `OrderController::shedule` (`/api/test/shedule`), `User::scopeOrderWorkers` | `User::scopeOrderWorkers` сортирует операторов в списке по графику «рабочего дня» с той же границей 19:00                                                                                                                        |
| Mango при определении оператора по добавочному берёт **календарный** день недели без сдвига 19:00                                                                                                                                                                                                | `MangoCallService::resolveOperator` (`Carbon::now()->format('l')`)                                                                                                                                                  | пн 20:00: распределение по формам — график вторника; оператор по звонку — график понедельника                                                                                                                                    |
| Входящий звонок Mango с 08:00 до 20:00 сначала получает `operator_id = 1000`                                                                                                                                                                                                                     | `MangoCallService::createIncomingOrder`                                                                                                                                                                             | звонок в 14:00 → `operator_id = 1000`; в 21:00 → `null`. Затем синхронный `OrderAddedEventListener` считает `1000` неназначенным и сразу распределяет. Сохраняется `1000` только для салона 16, где распределение не выполняется |
| Отчёты: кнопка «19:00-19:00» подставляет период **вчера 19:00 — сегодня 19:00** по времени браузера, независимо от текущего часа; фильтр отчётов — `orders.created_at BETWEEN from AND to`                                                                                                       | `client/pages/crm/reports.vue::fillDate('seven')` и копии (`report/classified.vue`, `report/inhouse.vue`, `report/justwe.vue`, `crm/reports_victory.vue` и др.); `ReportController`, `SummaryReportController`      | вт 10:00 → период пн 19:00 — вт 19:00; вт 20:00 → тот же период, заявки после вт 19:00 в него не входят                                                                                                                          |

Что **не найдено**:

- отдельной границы 18:00 для классифайдов или других типов источников, ни на сервере, ни в клиенте (поиск
  `18:00`, `setHours(18`, `hour = 18` дал только правило 18:30 для салона 9);
- настройки границы через интерфейс;
- хранения «расчётной даты» у заявки. В БД пишется только `created_at`; расчётный день вычисляется в момент
  распределения и не сохраняется.

### 2.2. Поведение до границы, на границе и после

Для салонов, кроме 9 (`Carbon::between()` включает границы):

| Момент `now()` | День недели графика  | Окно подсчёта нагрузки                            |
| -------------- | -------------------- | ------------------------------------------------- |
| 18:59:59       | сегодня              | `[вчера 19:00:00; сегодня 19:00:00]`              |
| ровно 19:00:00 | завтра               | `[сегодня 19:00:00; завтра 19:00:00]`             |
| 23:59:58       | завтра               | `[сегодня 19:00:00; завтра 19:00:00]`             |
| 00:00:00       | сегодня (новая дата) | `[вчера 19:00:00; сегодня 19:00:00]` — то же окно |

Пограничные эффекты кода (подтверждено чтением, не прогоном):

- `whereBetween` включает обе границы. Заявка с `created_at` ровно в 19:00:00 попадает и в окно предыдущего,
  и в окно следующего рабочего дня.
- Конец интервала задан как 23:59:59 с микросекундами момента создания объекта. В последнюю секунду суток
  `now()` может оказаться позже конца интервала, и тогда используется ветка «до 19:00» с текущим днём недели.
- `OrderController::shedule` сравнивает строго (`>` 19:00), остальные методы — включительно.

### 2.3. Где расчётный день влияет на работу

| Область       | Влияние (подтверждено кодом)                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| График        | выбор дня недели в `operator_schedules` (`monday` … `sunday` = 1) для распределения и проверки владельца повтора; в `DistributeService` — `programmatic_schedules`                                                                                                                                                                                                                                                                 |
| Нагрузка      | число заявок оператора в окне рабочего дня без повторов (`orders.retries IS NULL`) и без заявок сайтов `type_id = 4` (в `OrderAddedEventListener` и копиях; в `DistributeService` и `shedule` фильтра по типу нет)                                                                                                                                                                                                                 |
| Распределение | `User` с `role_id IN (2, 6)`, `users.showroom_id = салон заявки`, работающий в день графика, с минимальной нагрузкой → `orders.operator_id`. По комментариям в `ShowroomController::resetPasswords` `role_id` 2 — «операторы», 3 и 6 — «главные»; названия ролей в БД не проверены. Повтор (тот же телефон, тот же салон, `Order::phone4`) отдаётся прежнему оператору, если тот работает по графику, и получает `retries = N − 1` |
| Отчёты        | расчётный день не применяется автоматически. Отчёты фильтруют по `created_at` в выбранном периоде; «19:00-19:00» — только быстрый выбор периода. В отчёте по агентствам повторы (`retries IS NOT NULL`) считаются столбцом `Trash`                                                                                                                                                                                                 |

## 5. Связанные зависимости, не входящие в этап источников

Отмечены только для понимания найденных правил; здесь не проектируются.

- **Распределение** использует расчётный день (график и окно нагрузки), салон заявки, роль и тип сайта. Алгоритм —
  этап 6 ROADMAP.
- **Повторы**: признак повтора — тот же телефон в том же салоне за всё время (`Order::phone4`, суффиксное сравнение
  `LIKE '%телефон'`), счётчик `retries`. Правила V2 — этап 5.
- **Mango**: определение салона по аккаунту и ACD-группе, сайта по линии и оператора по добавочному — этап 8.
